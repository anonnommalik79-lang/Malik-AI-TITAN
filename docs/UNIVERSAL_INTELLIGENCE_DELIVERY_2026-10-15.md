Ветка: `codex/universal-intent-context-20261015`. По последнему решению пользователя изменения остаются в отдельной ветке. Main, Render, внешние аккаунты и инфраструктура не изменяются.

## A. Архитектура и первопричины

Исходный аудит: `UNIVERSAL_INTELLIGENCE_AUDIT_2026-10-15.md`.

Исправлены реальные несовпадения между уже существующими компонентами:

1. `Нет, в Word` не определялось как продолжение с новым форматом. Введён общий типизированный контракт последних требований: формат, язык, тон, аудитория, длина, списки, формулы. Он вычисляется из истории, не требует отдельного вызова модели и не превращает пользовательские предпочтения в системные полномочия.
2. Подсказки документов/презентаций/таблиц требовали HTML/CSV вместо существующих нативных экспортёров. Теперь модель пишет содержание; сервер создаёт и проверяет файл перед выдачей ссылки.
3. Фраза модели «создал файл» не подтверждала его наличие. Новый путь выдаёт owner-scoped ссылку только после успешного экспорта и сохранения исходника.
4. Смена формата могла затронуть текст подтверждения со ссылкой вместо самого документа. Сервер перечитывает исходник по artifact ID с проверкой владельца сессии.
5. `qaPassed: true` у правки кода не подтверждало build/tests. Для новой версии кода теперь отдельно фиксируются проверенная структура и отсутствие запуска тестов/сборки.
6. Добавлен узкий проверяемый цикл самокоррекции: невалидный JSON и дословное повторение отвергнутой версии. Максимум одна дополнительная попытка, без повторного запуска tool lanes и без увеличения конечного токенного лимита. Обычное приветствие остаётся одним streaming-ответом.

Не создано конкурирующего router/tool registry, нового storage backend, новых provider API или новой системы авторизации. Используются существующие God/Coder/OS/document/PPTX компоненты.

## B. Что реализовано

- Сохранение точного последнего запроса отдельно от извлечённых предпочтений.
- Для augmented attachment-контекста предпочтения берутся из исходного public request, а не из распознанного текста документа. Обычное `исправь этот код` не выключает текущий проект; только явный document/JSON/chat-only запрос сбрасывает старые Canvas-флаги.
- Наследование неконфликтующих требований при коротких уточнениях; отмена старого формата при `без файла` и `строго JSON`; сброс при новом предмете.
- RU/KK/EN и mixed preference detection; несколько опечаток и эмоциональные замечания. Это не доказательство качества перевода/редактирования модели.
- Сохранение новой версии содержания при просьбе вернуть прежний известный тон. Нет обещания восстановить произвольный визуальный макет или физическую страницу PDF.
- Реальные PDF, DOCX, PPTX, XLSX, CSV, Markdown, TXT, HTML, JSON document model и ZIP через существующий экспорт.
- DOCX/PDF/PPTX — не переименованный HTML. PowerPoint содержит редактируемый текст; длинный/слишком плотный слайд отклоняется, а не незаметно сокращается.
- XLSX: native `<f>` только при явном заказе формул. Закрытая грамматика, функции SUM/AVERAGE/MIN/MAX/COUNT/ROUND/ABS/IF, локальные адреса, лимиты длины/глубины/области. Внешние книги, network/DDE, макросы, неизвестные функции запрещены. По умолчанию импортированные строки `=...` остаются текстом.
- Формулы **не вычисляются сервером** и не имеют выдуманных cached values; книга просит Excel выполнить пересчёт при открытии. Кросс-листовые формулы и произвольные функции не поддерживаются.
- CSV защищает также пробельные префиксы и выражения вида `-2+...`; обычные отрицательные числа сохраняются числами.
- Версии immutable, lineage `revision-of`/`derived-from`, предыдущая версия остаётся доступной её владельцу.
- Abort/размер/ошибка экспорта/отсутствующий исходник не превращаются в фальшивую ссылку.
- Лимиты и admission проходят до выполнения. Auth owner не берётся из client email/history.

## F. Зависимости

- Текущие настроенные модели/ключи/квоты продукта остаются необходимыми; новый провайдер не добавлен.
- Для настоящей authenticated E2E нужна рабочая локальная/тестовая WorkOS-конфигурация. Это не утверждение о поломке регистрации на production.
- Для durable storage между перезапусками нужен существующий private S3/R2 backend. Без него ссылка помечена как runtime-memory; скачивание нужно выполнить до перезапуска.
- Для запуска пользовательского/сгенерированного кода необходим изолированный sandbox. Его отсутствие не обходится исполнением на основном сервере.
- Live browser/image/edit/search нужны соответствующие существующие production integrations и разрешённая тестовая сессия.

## G. Оставшиеся ограничения

Не реализовано: embedded-image block PDF, точечное редактирование физической страницы PDF, произвольное восстановление визуального оформления, server-side spreadsheet recalculation, универсальная проверка смысла и всех фактов. Не выполнено: полный authenticated browser→API→real model→download E2E и live safety/quality evaluation для всех моделей.

Контекст ограничен последними 64 turns. Legacy source preview ограничен 16 000 символами и явно помечает неполноту для модели. Это консервативный rule-based contract, не гарантия понимания любой формулировки. Обычные tool lanes сохраняют собственную проверку; generic JSON-repair не переигрывает их.

Сохранён immutable Markdown/source, а не двоичный файл. Перед выдачей проверяется настоящий экспорт; скачивание повторно рендерит источник. PDF/ZIP timestamps могут менять байты, поэтому SHA-256 в ответе относится **к текстовому исходнику**, а не к будущему download body. Это явно написано в интерфейсном тексте ссылки.

Проверка generic repair ловит синтаксический JSON и дословное повторение; она не доказывает смысловую правильность. Provider fallback внутри существующих движков не отменяется. Форматирование и quality требуют дальнейших живых оценок.

## J. Итог качества

Instruction following/steerability/context: проверенный активный контракт; живое качество ещё не измерено. Tools/artifacts: проверенные локальные native bytes и owner/version/receipt boundaries; не все production tools. Self-correction: одна ограниченная проверяемая попытка, не общий «самопроверяющийся интеллект». Multilingual: RU/KK/EN/mixed intent tests, не оценка перевода. Safety: owner/quotas/формулы/CSV/нет фиктивного исполнения; нет заверения о полной prompt-injection защите.

Performance: при 1 000 локальных вызовах короткого уточнения resolver занимал примерно 0,1–0,7 мс/turn в разных запусках, включая параллельную нагрузку сборки; это не production latency модели. Приветствие: один вызов/обычный streaming. Конверсия существующего документа: ноль model calls. Generic repair: максимум одна дополнительная попытка в разделённом исходном лимите; переиспользуются существующий planner/явный бюджет, новый фиксированный потолок ответа не введён. Memory/RSS, production concurrency, стоимость живых ответов и долгосрочное качество этим тестом не измерены.

UX: прежняя компоновка, обычные ссылки/меню, честное предупреждение runtime-memory, нет обещания созданного файла до реального экспорта. Полная миссия ещё не может быть объявлена выполненной.
