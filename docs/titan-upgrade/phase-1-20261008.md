## Actual defects and changes

1. A thrown SSE reader error discarded text already received by background persistence. State now lives outside the try block; the failed turn retains its actual partial content and execution trace. The added test failed before the fix.
2. A lost response-header deadline could POST the same question again with a newly allocated turn ID while the first job was already running. Header failure now reports uncertainty without duplicating admission; a late response body is cancelled. Existing known-turn polling and bounded read-only recovery remain.
3. Background persistence parsed individual `data:` lines instead of the complete multiline event. A small shared contract now handles multiline LF/CRLF JSON and event-header-only types. UTF-8 fragmentation, malformed payloads and heartbeat handling are tested.
4. Legitimately repeated text chunks could be mistaken for cumulative snapshots. The existing producer now labels deltas; client, persistence and audit use matching merge semantics. Explicit snapshots are monotonic, old snapshots do not shrink the answer, and divergent recovery cannot replace the received answer.
5. Failed or empty completion events could be reported as success. Client recovery, persistence and audit retain truthful failures. A final `done.content` snapshot is delivered before completion, including its missing tail.
6. Founder telemetry duplicated cumulative text, dropped large split frames and could interrupt the user's stream after a parse exception. Audit records the correct bounded prefix, redacts secrets, retains partial failure content, and forwards original bytes even when audit parsing fails. The final-tail test failed before the fix.
7. Browser personal memory used one unowned global key across accounts. Memory now uses schema-v2 account keys set by the existing authenticated account boundary. Unknown identity cannot read or write memory; sign-out clears active scope. Legacy v1 data remains unchanged and is **not automatically claimed by the next login**. The new test failed on the former unscoped read.
8. Storage failures no longer produce a false successful memory-save acknowledgement or clear the draft prematurely.
9. The monochrome test contradicted the new request-animation stylesheet in the original base. The test now requires final surface authority and permits only a named motion-only follow-up, rejecting paint properties, imports and external URLs. No layout, colour or animation was changed by this patch.
10. Five Voice regression scripts used Windows paths as ESM import URLs. They now construct proper file URLs, and the entire existing Voice suite runs on Node 22/Windows.

No competing chat, SDK migration, large dependency, new model ID, authentication bypass, raw reasoning exposure or arbitrary execution of model-written code was added. AI SDK guidance informed the transport/error contract while retaining the existing pipeline. React guidance informed versioned browser storage and browser-only scope rather than SSR-shared mutable user state.

## Performance and security impact

- No added package, timer, background service or provider search. The abandoned-header path removes a possible extra POST and duplicate paid generation.
- Diagnostic only: 10,000 in-process delta merges / 50,000 characters took approximately **0.9 ms** in the final QA fixture run. This is not production time-to-first-token or network latency.
- Shared helper transpiles to **2,206 bytes**, **842 gzip bytes** without comments. This is a helper-size measurement, not measured total client bundle growth.
- Answers retain the existing **1,500,000 UTF-16-code-unit** ceiling. The maximum event-frame buffer is **9,065,536 code units**, allowing JSON escape overhead; unusually large audit frames can consume more temporary RAM than the old lossy 100k buffer. Peak process RAM/CPU under real concurrent production load was **not measured**.
- The existing terminal-result cache stays bounded to 32 MiB / 128 turns; pending work is not newly evicted. Audit stores only a 16k text prefix; memory remains 40 items × 600 chars with 4,200-char outgoing context.
- Accounts cannot access another account's memory through the normal UI/context helpers, and server background-turn ownership contracts remain intact. Browser-local storage is not a substitute for encrypted cloud memory or protection from another person inspecting the same device's storage.
- No token/config values committed. Secret redaction remains tested. Telemetry cannot invent success or break an otherwise valid stream.
- The existing old dashboard-history migration deserves a separate owner-proof audit before claiming complete legacy cross-user migration safety. Cloud user-memory synchronization was not implemented here.
