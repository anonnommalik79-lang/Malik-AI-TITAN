## 3. Жёсткие правила

- Если тест не запускался — NOT_TESTED. Если упал — FAIL, исправь причину. PASS — только при реально пройденных обязательных проверках. Не выдумывай URL, источники, цитаты, результаты.
- Сгенерированный код запускай только изолированно: шаблон — `lib/games/smoke.ts` (дочерний `node --permission`, `--allow-fs-read`/`--allow-fs-write` только на временную папку, пустое env, таймаут и kill, ограничение вывода, по одному запуску за раз). Бесконечные циклы ремонта запрещены: не больше 2–3 раундов, остановка, если раунд не улучшил результат.
- Внешние действия (отправка сообщений, публикация, платежи, удаление данных) — только после явного подтверждения пользователя. Используй существующий механизм подтверждений `lib/os` actions.
- Секреты не должны попадать во frontend, логи и репозиторий. Платные сервисы без разрешения не подключать.
- Не дублируй существующее: intent detection, роутер моделей, реестр инструментов `lib/os/tools/registry.ts`, оркестратор `lib/os/planner.ts` / `task-graph.ts` / `executor.ts`, активность `ExecutionReporter` / `MalikLiveActivity`, библиотеку артефактов `lib/os/library.ts`.
- Каждая система подключается к основному чату (`app/api/stream/route-impl.ts`) через детектор намерения и возвращает реальный результат, а не описание.

Клади `PROOF_PASSPORT.json` в каждый ZIP (`lib/server/project-artifact-store.ts`). Тест: ни один путь не выдаёт PASS без запущенных проверок.
2. **Self-Build** (новый модуль, например `lib/selfbuild/`): REQUIREMENTS → PLAN → многофайловый код (файлы между маркерами, как в Game Studio) → `analyzeProject` (`lib/work/code/diagnostics.ts`) → изолированный запуск `node --test` во временной папке через дочерний процесс → разбор результатов → ограниченный ремонт → ZIP + паспорт. Для статических веб-проектов: запуск в sandbox + браузерная проверка в превью чата (как у игр). Сборка Next.js/npm install на Render — NOT_TESTED с объяснением или через внешний исполнитель `lib/website/engine/executor.ts` (только если `WEBSITE_EXECUTOR_URL` реально настроен). E2E: запрос «сделай CLI-утилиту с тестами» → тесты реально запускаются → в паспорте видны команды и результаты; сломанный тест исправляется в ремонте.
