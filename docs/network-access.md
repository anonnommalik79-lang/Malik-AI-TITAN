# Malik AI: доступ в сетях с ограничениями

`ERR_ADDRESS_INVALID` возникает до загрузки приложения: Chromium считает адрес
или порт назначения недопустимым. Скриншот не доказывает конкретный источник:
нужно проверить DNS, hosts, браузерный прокси и правила сети на самом ПК.

Код приложения не может гарантировать доступ через запрет администратора сети.
Нужен разрешённый доступ к домену; автоматического обхода правил здесь нет.

## Что добавлено

- `/connection`: обычная HTML-страница без React, внешних шрифтов и JavaScript,
  с проверкой сервера, режимом совместимости и списком зависимостей для сети.
- `/dashboard?connection=poll`: после входа в аккаунт фоновые запросы получают
  короткое JSON-подтверждение HTTP 202 (`Prefer: respond-async`), а браузер читает
  результат короткими HTTPS GET. SSE существует только между моделью и сервером
  и внутри браузера; по сети клиенту SSE не передаётся. Готовый ответ появляется
  целиком. Не создаются повторные генерации при ошибке очередного GET.
- Обычный `/dashboard` использует прежний потоковый режим. Гостевой чат также
  сохраняет прежний режим: выдача фоновых ответов остаётся только владельцу
  аккаунта. 401/403/404/429 завершают polling, остановка отменяет чтение.
- `/guest` сохраняет точный `RENDER_EXTERNAL_URL` текущего сервиса. Чужие
  onrender-адреса и поддельные Host не принимаются. WorkOS OAuth продолжает
  использовать канонический домен и существующие PKCE-проверки.
- `public/malik-network-check.ps1`: проверка DNS/hosts/HTTP на проблемном Windows
  ПК без изменения сетевых настроек. Не проверена на реальном Windows в этой
  среде; предназначена для Windows PowerShell 5.1 и PowerShell 7.

## Настройка сети и адреса

Для сайта и обычного текстового чата разрешить `malikaiworld.world` по TCP 443,
включая `/api/*`, `/_next/*` и локальные ресурсы. Модели вызываются сервером:
доступ браузера к доменам OpenAI, Anthropic, Groq и другим текстовым API не нужен.
Вложения и отдельные медиафункции могут использовать дополнительные URL.

Для стандартного WorkOS-входа нужны `api.workos.com` и домены выбранного
провайдера Google, Apple или Microsoft. Точный набор проверить по цепочке
редиректов вашей настроенной авторизации.

Дополнительный адрес взять из Settings → Custom Domains → Render Subdomain
именно существующего Malik AI сервиса. Не угадывать URL по имени сервиса.
Проверить, что адрес разрешён администратором сети, а настройка Render Subdomain
включена. `render.yaml` объявляет `renderSubdomainPolicy: enabled`; существующий
сервис без управления этим Blueprint требует отдельного изменения в Dashboard.
Не создавать второй сервер и не менять DNS вслепую.

После ручного деплоя проверить `<точный-адрес>.onrender.com/api/health`, затем
`<точный-адрес>.onrender.com/guest`: перенаправление должно сохранять этот адрес.
WorkOS-вход на дополнительном адресе требует отдельной настройки callback и
полного теста PKCE, поэтому текущая версия не переключает OAuth автоматически.

## Проверка на проблемном ПК

Скачать `https://malikaiworld.world/malik-network-check.ps1` с доступного
устройства и перенести файл на проверяемый компьютер. В PowerShell:

```powershell
.\malik-network-check.ps1
```

Если выполнение скриптов запрещено политикой, передать файл администратору.
Не менять execution policy, hosts, DNS или настройки прокси для обхода запрета.
Результат на другом компьютере не подтверждает исправление проблемной сети.

Источники: [Chromium error codes](https://chromium.googlesource.com/chromium/src/+/HEAD/net/base/net_error_list.h),
[Render custom domains](https://render.com/docs/custom-domains),
[Render environment variables](https://render.com/docs/environment-variables).

## Проверка изменения

| Граница | Проверено | Ограничение |
| --- | --- | --- |
| Async POST → серверный поток → сохранённый ответ | 12 новых сетевых проверок прошли | Модель и сессия представлены тестовыми данными |
| JSON GET → существующий формат событий чата | Unicode, источники, успешный/частичный ответ, отмена, таймаут | Исполнен реальный клиентский транспорт в Node |
| Доступ к истории | 13 проверок владельца прошли | Вход и облачный IO подменены в тестах |
| Обычный поток и восстановление | 11 проверок целостности и 8 проверок фоновых ответов прошли | Локальные сценарии с контролируемыми сбоями |
| Авторизация | Регрессии канонических OAuth-редиректов прошли | Реальный WorkOS-вход в этой среде не проверен |
| Production-сборка | TypeScript, webpack production build и lint изменённых файлов прошли | Изменение ещё требует ручного деплоя |
| Браузер, Windows, проблемная сеть | Не подтверждено | Chromium не установлен; локальный HTTP недоступен из тестового процесса; доступ к школьному ПК отсутствует |
