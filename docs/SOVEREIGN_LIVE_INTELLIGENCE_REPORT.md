# MALIK Sovereign Live Intelligence — аудит и проверка

Дата аудита: 2026-10-11. Доставка разрешена пользователем 2026-10-12 (Asia/Almaty). Репозиторий: `anonnommalik79-lang/Malik-AI-TITAN`.
Ветка: `codex/sovereign-live-intelligence-20261011`.
Начальная база: `c3e504b8`; интегрирован актуальный `main` с Accuracy Engine: `9d90e5fb`.

Реализована инфраструктура оценки свежести, ограниченного поиска, источников и обновляемого индекса. Динамический ответ формируется после получения подходящих доказательств. При отказе источников система сообщает об отсутствии подтверждения. Реальное покрытие новостей, семантическая достоверность всех утверждений и поведение production-моделей этим изменением не доказаны.

## 1. Причины устаревших ответов и найденная архитектура

Основной чат вызывает `malikGodAnswer` в `lib/malik-god-router.ts`, затем выбранную пользователем модель через `runStrictMalikModel` в `lib/server/malik-model-router.ts`. Существующие `responseDepth` balanced/deep/ultra соответствуют Быстро/Глубоко/MAX. Выбор модели, авторизация, работа подключённых сервисов и формат событий сохранены.

До изменения свежесть определялась несколькими несогласованными регулярными выражениями. Запросы о сильнейшей ИИ-модели без слова «сегодня», новые технологии и некоторые казахские запросы пропускались. Переводы, базовые знания и история иногда запускали поиск. Сборщик основного чата мог запустить до трёх запросов с восемью адаптерами каждый; Groq scout добавлял отдельный модельный вызов. Research и Voice имели отдельные правила и пределы.

Не было единой политики временных окон, TTL доказательств, circuit breaker и регулярно обновляемого реестра моделей. RSS publication, GDELT crawl time, HF repository modification и дата прочтения не были последовательно разделены. Читатель страниц не извлекал явные publication/update метаданные и не закреплял проверенный DNS-адрес на соединении и перенаправлениях. Существующий факт-аудит проверяет числа и цитаты механически; он не доказывает семантику произвольного утверждения.

В репозитории найдены Serper, Tavily, Brave, Jina, Bing RSS, Google News, Wikipedia, GDELT и Groq scout для главного чата; SearxNG и DuckDuckGo в Research/Voice. SerpApi используется для изображений. Текстовых адаптеров Exa и Google CSE не найдено. Их подключение и новые платные сервисы не добавлены.

## 2. Компоненты и поведение

- Каждое сообщение основного маршрутизатора, включая мгновенные ответы, проходит `classifyFreshness`: STATIC/CURRENT/MIXED/LIVE/UNCERTAIN. RU/KZ/EN, контекстные продолжения, явный поиск и отказ от поиска учитываются. Классификатор эвристический.
- Динамические факты используют реальные существующие адаптеры, официальные ленты и GitHub stable release endpoint. Историческим запросам не приписывается текущий год. Математика, перевод и расчёты с заданными числами не требуют веб-источника.
- Общий search engine используется основным чатом и Research/Voice: ограниченный fallback, отмена запросов, общий пул двух активных провайдеров на процесс, TTL-кеш и circuit breakers. В Глубоко/MAX запрашиваются дополнительные провайдеры в пределах общего бюджета; это не гарантирует независимость публикаций.
- Временные окна: сегодня/вчера в Asia/Almaty, 24 часа, семь дней, текущий месяц/год. ICU определяет смещение, включая изменение часовой зоны Казахстана и DST других зон. «Последняя модель на сегодня» отличается от «модель, выпущенная сегодня».
- Ранжирование учитывает соответствие вопросу, реальный домен URL, официальный источник, временное окно и возраст. Старый официальный документ может быть полезнее свежей непроверенной SEO-статьи. Дата индексирования не подтверждает дату релиза.
- Датированные события вне окна и недатированные новости не становятся доказательством события в этом окне. GitHub latest stable — отдельное подтверждение текущей версии даже при старой дате публикации релиза. HTML-листинг без даты остаётся упоминанием.
- Внешний текст санитизируется и передаётся модели как недоверенные данные. Фиксируются буквальные противоречия размеров контекста моделей; универсальный семантический поиск противоречий не реализован.
- MalikCoder и прямой анализ вложений получают доказательства по исходному вопросу; извлечённое содержимое файла не используется для публичного поиска. Подготовленные на сервере источники передаются основному маршрутизатору без повторного поиска. Private connector commands сохраняют отдельную account evidence цепочку.
- Динамические ответы буферизуются до Accuracy/Truth/freshness checks. Недопустимые номера цитат и URL заменяют ответ честным сообщением. Для объединённых веб- и подключённых источников сохраняется общая нумерация. Это проверка ссылок и наличия доказательств, а не доказательство каждой фразы.
- Используются существующие progress/source/done события и один окончательный ответ. Добавляется серверная дата проверки. Её точный служебный footer не считается неподтверждённым внешним фактом. Собственных изменений TSX/CSS относительно актуального main нет.
- SSRF-защита прямого читателя проверяет все DNS-ответы, блокирует закрытые/локальные/metadata адреса, закрепляет адрес соединения и повторяет проверку на каждом redirect. Есть ограничения времени, размера и типов ответов. Для Jina предварительно проверяется публичный адрес; удалённый сервис самостоятельно выполняет чтение.
- Public query guard исключает обнаруженные секреты, контакты и приватные идентификаторы; для некоторых смешанных задач извлекается только публичная тема. Это эвристика, не универсальная DLP-система. Ключи остаются на сервере.

## 3. Обновление индекса и реестра

`.github/workflows/live-knowledge-update.yml` планирует запуски в 02:37, 08:37, 14:37 и 20:37 UTC. Web-сервер и Render Free для них не нужны. Workflow использует Node 22 и встроенные модули, без npm install и LLM-запросов. Результат записывается только в `knowledge/live-index/index.json` отдельной data-ветки, без force push; код main и Render не изменяются. Есть ручной workflow_dispatch, общий concurrency lock и предел шесть минут.

22 фиксированные ленты охватывают официальные новости OpenAI/Anthropic/DeepMind/Mistral/xAI, HF-репозитории OpenAI/Google/Meta/DeepSeek/Qwen/Mistral, GitHub Next.js/React и девять тематических Google News feeds. Это ограниченный список, не весь интернет. Новые известные семейства и незнакомые имена моделей в HF-репозиториях обнаруживаются без выдуманного релиза; неизвестный владелец — candidate. Произвольные новые разработчики не обнаруживаются глобальным crawler автоматически.

Индекс содержит до 500 записей и 200 моделей, источники, тему, publication/repository-update/unknown, время проверки и отдельно health каждой ленты. Реестр хранит имя/разработчика/семейство/версию, announcement/availability, модальности, возможности, ограничения, доступ, первоисточники, проверку и статус. Неподтверждённые свойства остаются пустыми/null. HF lastModified не превращается в announcement. Primary mention отличается от release-announcement и candidate; статус announcement основан на явном датированном первоисточнике и распознанной формулировке, а не полной семантической верификации статьи.

URL hash обеспечивает дедупликацию; ETag/Last-Modified и 304 — инкрементальное обновление. Повторная проверка не изменяет дату публикации. Имя исходной ленты сохраняется при чтении JSON; retrieval помечает копию как verified-index. Это позволяет HTTP 304 действительно обновлять checkedAt после восстановления предыдущего индекса. Записи старше 90 дней с последней успешной проверки удаляются. JSON ограничен 2 MiB, ошибки — последними 50, запись локального файла атомарна. Отказы не стирают предыдущее успешное состояние. Полный отказ завершает workflow ошибкой и сохраняет диагностику; частичный успех сохраняет отдельные ошибки лент. `lastSuccessAt` означает хотя бы одну успешную ленту, а не полное покрытие.

Сервер загружает индекс по фиксированному URL с таймаутом 1,8 секунды, кешем 15 минут и объединением одновременных запросов. Если репозиторий закрыт, нужен существующий `GITHUB_TOKEN` либо серверный `MALIK_KNOWLEDGE_GITHUB_TOKEN` с чтением содержимого репозитория. Токен не выводится клиенту. Недоступный/просроченный индекс не блокирует поиск на лету. Health становится stale после 48 часов; данные индекса старше запроса TTL требуют перепроверки страницы для динамического ответа.

**Активация расписания зависит от main и GitHub Actions:** GitHub запускает schedule из default branch. Пользователь отдельно разрешил доставку в main 2026-10-12. В момент составления отчёта workflow ещё не выполнялся на GitHub. После доставки нужны разрешённые Actions и запись data-ветки; приватному приложению также нужен доступ к индексу. Schedule может задерживаться/пропускаться и отключаться в публичном репозитории после длительной неактивности. Пропуск не исправляется фиктивной свежестью: используются age/health, следующий идемпотентный запуск и поиск по запросу. Автоматическая внешняя watchdog-система не добавлена.

## 4. Реальные проверки внешних источников

Без LLM-генераций и платных ключей выполнен ограниченный live updater. Получено 154 уникальные записи и 47 модельных записей в версии парсера на момент прогона, 114 554 байта JSON. Успешны 11 из 22 лент: OpenAI RSS, Anthropic HTML, DeepMind RSS, xAI HTML, шесть HF API и GitHub Next.js. 11 отказали: Mistral, GitHub React и все девять тематических Google News feeds. Частичный результат не доказывает покрытие всех новых моделей; последующие расширения парсера отдельно проверены фикстурами.

Живой query smoke A/C/D не получил подходящих источников за примерно 10 секунд на запрос в этой среде. B после корректировки ограниченного таймаута официальных лент получил один подходящий официальный источник DeepMind за 3,067 секунды, один provider call. Источник имел явную publication date; полная страница не была подтверждённо прочитана, доступны feed headline и метаданные. Повторяемость нестабильна: предыдущие B-прогоны также завершались таймаутами. Получение одного источника не доказывает, что обнаружена самая новая модель во всём каталоге.

Serper/Tavily/Brave ключи в среде отсутствуют; их настоящие authenticated API не проверены. Их HTTP-контракты и fallback проверены фикстурами. Bing RSS/Google News не дали полезных результатов в query smoke; Jina/GDELT не успели быть проверены в пределах fast бюджета. Отдельная успешность DuckDuckGo/SearxNG/Wikipedia в интернете этим прогоном не доказана. На основании mock-тестов ни один из них не объявляется работающим в production.

## 6. Замеры до/после и ресурсы

Полный воспроизводимый JSON: [live-intelligence-validation.json](live-intelligence-validation.json). База политики — `c3e504b8`. Набор 40 static + 35 dynamic заранее фиксированных RU/KZ/EN запросов используется также в тестах; это не независимая выборка.

| Метрика | До | После |
|---|---:|---:|
| Правильный выбор поиска | 56/75 (74,7%) | 75/75 (100% на этом наборе) |
| Лишний поиск | 8/40 | 0/40 |
| Пропущенный динамический поиск | 11/35 | 0/35 |
| p50 выбора поиска, ms | 0.0019 | 0.0987 |
| p95 выбора поиска, ms | 0.0062 | 0.2657 |
| Максимум provider calls главного чата | До 24 + необязательный Groq scout | Быстро 4, Глубоко 6, MAX 8 |

Измеряется выполнение политики в процессе, не latency полного ответа. Добавленная классификация медленнее старого regex, но её p95 остаётся меньше миллисекунды на этом наборе. Для production p50/p95 генерации, частоты устаревших ответов, доли семантически подтверждённых утверждений и стоимости ответа нет достоверного измерения. Они не подменяются цифрами из mock-тестов.

Контролируемый cache benchmark после GC: 128 записей × 8 источников, 2,620,480 байт сериализованных данных; прирост heap 2.18 MiB. Это один замер отдельно созданного кеша, не расход памяти всего Next.js/Render и не peak RSS production.

| Ресурс | Предел/поведение |
|---|---|
| Search engine | 1/2/3 queries, 4/6/8 provider calls, 10/14/18 s для fast/deep/max |
| Попытка provider | Обычно 3,5 s, официальные ленты/releases 5,5 s; жёсткий предел 6 s и общий deadline |
| Главный gather + чтение | Общий deadline 22 s; 2/4/6 выбранных page reads, одновременно не больше двух |
| Search cache | 128 entries, до восьми ограниченных источников на entry; LIVE TTL 60 s, остальные dynamic 300 s, STATIC 1200 s |
| Circuit state | До 32 имён; cooldown 60 s после трёх ошибок |
| Чтение страницы/feed | До 1 MiB на ответ, ограниченные redirects; snippet/page context обрезан |
| Updater | 22 feeds, два одновременно, 6 s/feed, 500 items, 200 model records, JSON до 2 MiB |

Fixture fallback: Быстро/Глубоко/MAX сделали 2/4/6 вызовов, с 1/2/3 успешными переходами на резерв по queries; повтор из кеша сделал ноль provider calls. Полностью пустые providers достигли строго 4/6/8 calls. Это контролируемая симуляция, не процент успешности реальных сервисов.

Затраты fixture-прогонов и public feed smoke: ноль платных поисковых и LLM-вызовов. Тарификация рабочих API зависит от уже настроенных аккаунтов; USD/request для production неизвестен. Число вызовов и outcome/time/cache/fallback регистрируются в server execution/логах. Денежный бюджет через billing API не добавлен. За минутами GitHub Actions следит владелец аккаунта; постоянные фоновые циклы и Render-запуски не используются.

## 8. Повторение проверок

Из каталога приложения:

```sh
npm run test:live-intelligence
npm run test:accuracy
npm run test:accuracy-routing
npm run test:truth
npm run test:fact-audit
npm run test:voice
npm run test:web-recovery
npm run typecheck
node --expose-gc scripts/benchmark-live-intelligence.mjs
```

Явные внешние проверки, без LLM и оплачиваемых ключей:

```sh
node scripts/check-live-search.mjs --case=B
npm run knowledge:update -- /tmp/malik-public-index.json
```

Browser suites требуют доступный Playwright Chromium. Полный production/мобильный end-to-end тест и повторный smoke с реальными настроенными search credentials остаются проверками перед отдельным разрешённым deployment.

## 9. Оставшиеся ограничения и доставка

Реестр не обещает все мировые модели. Даты availability и сложные характеристики автоматически не выводятся из догадок. Русско-казахско-английское соответствие и извлечение названий эвристические. Первичный домен и совпадение числа не доказывают смысл статьи. Цитаты проверяются по существованию, а не полной entailment каждой фразы. Старые официальные документы сохраняются, но могут потребовать явной свежей проверки для текущего свойства.

Расписание добавлено для default branch. Успешный scheduled запуск ещё не подтверждён. Нет глобального semantic verifier, внешнего watchdog, нового search account или доказанной надёжности всех providers. В этой сети часть RSS/search недоступна. Мобильная визуальная проверка и production latency/cost/factual-coverage measurements не выполнены.
