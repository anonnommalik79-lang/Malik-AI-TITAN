# Malik Work — лимиты и серверная защита

* Бесплатный зарегистрированный пользователь: **6 запросов за скользящие 7 дней**.
* MalikAI Plus (plan `pro`): **20 запросов за 5 часов** и **100 за скользящие 7 дней** (оба ограничения действуют одновременно).
* plan `ultra`: 40 / 5 часов и 200 / 7 дней.
* Проверенный владелец (`owner`): без ограничений. Гость должен войти.
* Лимиты Work не влияют на обычный чат, генерацию изображений, видео и кредиты на презентации.
* Серверный допуск: `/api/stream` и `/api/ai/chat` при `workspaceMode=work`. Клиент не может назначить себе платный тариф; используется `resolveRequestEntitlement`.
* В интерфейсе Work: кнопка «Лимиты» в верхней панели и `GET /api/work/limits`.
* Конфигурация: `WORK_PLUS_5H_LIMIT`, `WORK_PLUS_WEEKLY_LIMIT`, `WORK_ULTRA_5H_LIMIT`, `WORK_ULTRA_WEEKLY_LIMIT`.
* Хранение: объектное S3/R2, `WORK_QUOTA_BUCKET` (необязательно, берётся существующий private/media/R2 bucket), credentials и endpoint — как для `lib/server/private-json-store.ts`. Списания защищены условной записью `If-Match`/`If-None-Match`; при недоступном хранилище Work для пользователей закрывается с 503, вместо сброса счётчика.
* Списывается один принятый Work запрос. Если выполнение завершилось ошибкой до выдачи текста, резервирование возвращается. При частичном стриминге запрос считается использованным.
* Проверка логики: `node --experimental-strip-types --no-warnings scripts/verify-work-quota.mjs` (запуск из каталога sovereign-hub-ui).

Развёртывание и реальное хранилище требуется проверить отдельно; этот коммит не запускает Render.
