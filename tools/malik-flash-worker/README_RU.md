# MALIKII Flash Chrome Worker — эксперимент

Этот отдельный worker реализует протокол, который теперь использует MalikLLM Flash.
Он не требует Gemini API, но требует Node.js 22+, Chrome и установленный playwright-core.

## Запуск локального worker

1. В папке tools/malik-flash-worker выполните npm install.
2. Установите переменную MALIK_FLASH_WORKER_SECRET (случайная строка длиной от 24 символов).
3. Запустите npm start.
4. При первом запросе Chrome откроется с отдельным профилем пользователя.
5. Google может попросить войти вручную и дать согласие. Не обходите CAPTCHA и другие ограничения.
6. Рабочий локальный адрес: http://127.0.0.1:8793/v1/ask.
7. Запрос требует Authorization: Bearer <секрет> и protocol: malik-flash-worker-v1.

## Требования для связи с Render

**Локальный адрес 127.0.0.1 недоступен серверу Render!** Для Render нужен отдельно разрешённый HTTPS worker
с корректно настроенным прокси, защитой от посторонних запросов и раздельными профилями каждого пользователя.
Не публикуйте worker с аккаунтом создателя на всех пользователей; не храните общий Google cookie.
Массовое автоматизированное использование Google AI Mode не является официальным API и может блокироваться
или противоречить условиям Google. Лучший production-способ — поддерживаемый API поиска и анализа изображений.

Переменные на стороне Next.js:
- MALIK_FLASH_WORKER_URL=https://ваш-изолированный-worker/v1/ask
- MALIK_FLASH_WORKER_SECRET=тот_же_секрет
- MALIK_FLASH_ISOLATED_WORKER=1
- NEXT_PUBLIC_MALIK_FLASH_PREVIEW=1 только после независимого E2E и ручного разрешения публикации.

Переменные самого worker: MALIK_FLASH_WORKER_PORT, MALIK_FLASH_PROFILE_DIR,
MALIK_FLASH_HEADLESS=1 (только после ручного входа), MALIK_FLASH_CHROME_PATH при необходимости.

## Что реализовано

- Пользовательский браузерный профиль по HMAC-scoped userScope.
- Независимый Google AI Mode диалог для каждого chatScope с сохранением URL.
- Загрузка до 4 настоящих PNG/JPEG/WebP через Chromium file chooser, а не вставка URL картинки в вопрос.
- Сохранение текста ответа вместе с многострочным кодом, ссылками и проверкой завершения.
- Полезные сообщения вместо ложного «успеха», если Google поменял UI или требует подтверждение.
- Мягкая очередь запросов, квота 30 в час на браузерный профиль.

## Что не гарантируется

Живой Google UI может поменять разметку; Playwright не обходит CAPTCHA и лимиты.
Отправка изображения браузером не доказывает семантический анализ каждого пикселя:
ответ Google следует проверять на реальном тестовом изображении. Необходимы E2E-тесты
с двумя разными аккаунтами и подтверждение правомерности доступа до массовой публикации.
